# 系统组成推理

框架检测是辅助证据，绝不是组件清单。渲染展示页之前，先构建一份针对该产品的组成关系图。

## 四个层级

1. **应用外壳** —— 全局头部、侧边导航、工作区、路由标签页、页脚、浮层层。
2. **页面模式** —— 列表/搜索、详情、编辑/表单、仪表盘、工作流、弹窗/抽屉。仅从重复的 DOM/CSS/路由 chunk 结构推断。
3. **复合组件** —— 筛选条、实体头部、数据工作区、主从面板、工具栏、时间线、卡片组。
4. **基础原语** —— 控件、标签、表格单元、反馈组件、分页、选择器、对话框。

为每个升级的条目捕获其父子链接。页面样例只有在条目关系被观测到时才能进行组合，否则标注 `原型组合推断`。

## 证据与覆盖

为每个层级建立带 `id`、`kind`、`children`、`provenance` 和 `evidence` 的图记录。检查所有编译 CSS 与路由 chunk，而非仅检查入口样式表。CSS 根前缀族、路由 chunk 名、重复的选择器子树与 JS 注册，都可以确立 `inferred` 级的组成。不要把某个框架的完整目录当成产品清单。

预览必须展示覆盖度小结：已观测/已推断的外壳、页面模式、复合组件与基础原语。若某个层级没有证据，写明 `未找到证据`；不要用库模板去填充它。
